ngx_l402 - L402 Nginx Module

MCP Tool Pricing

A remote MCP server takes every message as a POST to one URL, with the tool to run in the body. With plain l402 on; every message costs the same and one token opens every tool. l402_mcp on; prices and binds each tool call instead, without adding payment code to the server:

location /mcp {
    l402                      on;
    l402_mcp                  on;
    l402_mcp_upstream_validates on;          # see "Trust model" below
    l402_amount_msat_default  1000;          # price of a tool without its own line
    l402_mcp_tool  summarize  5000;          # a tool with its own price
    proxy_pass                http://mcp-server;
}
  • Discovery is free. tools/list and every other method pass through, so a client can see what is for sale before paying.
  • Each tool has its own price. A tool without an l402_mcp_tool line costs the default, so a new tool is never free by accident.
  • A token buys one tool. The macaroon carries McpTool = <name> and McpMethod = <method> next to the path and HTTP method, so a token bought for a cheap tool is rejected on an expensive one, and one bought for tools/call doesn’t open prompts/get of the same name. With l402_realm the token is bound to the realm instead of the path, so it also works for the same tool and method on any other path in that realm.

Trust model — read this first

The module never reads the request body. It reads the tool from the headers the 2026-07-28 Streamable HTTP transport mirrors from the body:

POST /mcp
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: summarize

The same spec requires the MCP server to reject a request whose headers disagree with its body (400, HeaderMismatch). That check is what stops a client from sending Mcp-Name: search and calling summarize in the body.

So header-based pricing is only as strong as the upstream’s validation:

  • The upstream must implement 2026-07-28 or later and enforce the header/body check. Against a server that ignores the headers, a client can pay for the cheapest tool and run any other.
  • You declare that it does with l402_mcp_upstream_validates on;. The module can’t see whether the upstream checks, and the client’s MCP-Protocol-Version can’t vouch for it either, because the client chooses it. nginx refuses to start with l402_mcp on and no declaration.
  • The client’s version is checked as well: the headers are trusted only when MCP-Protocol-Version is a real date, 2026-07-28 or later. Anything older is refused (see below).

How requests are handled

RequestResult
Anything but POST (e.g. an older client’s GET stream or session DELETE)405, Allow: POST
A method not in l402_mcp_charge (e.g. tools/list)Passes through free
tools/call with Mcp-NameCharged at that tool’s price; 402 until paid
No MCP-Protocol-Version400, -32020
MCP-Protocol-Version older than 2026-07-28, or not a revision date400, -32022
No Mcp-Method400
tools/call, resources/read or prompts/get without Mcp-Name400
A duplicated Mcp-Method, Mcp-Name or MCP-Protocol-Version400
An Mcp-Name that is malformed, doesn’t decode, or decodes to control characters400

Every other 400 carries a JSON-RPC error with code -32020 (HeaderMismatch). An unsupported version gets -32022 (UnsupportedProtocolVersion) with data: {"supported": ["2026-07-28"], "requested": "…"}, so a client that also speaks 2026-07-28 can retry with it. requested echoes the client’s value only when it is a real date, and is "" otherwise. Neither carries an id, the shape the spec uses for transport-level rejections.

A request the headers can’t vouch for is refused rather than charged at the default price: a default-priced token for a request that can’t be tied to a tool would let a cheap payment open an expensive tool.

Mcp-Name values outside plain ASCII arrive base64-encoded (=?base64?c3VtbWFyaXpl?=). They are decoded before the price lookup, so an encoded tool name still gets its own price. Only padded, standard-alphabet base64 is accepted, the form the spec’s examples use.

OPTIONS preflight requests can pass through with l402_exempt_methods OPTIONS;, which is checked before the 405.

Directives

DirectiveMeaning
l402_mcp on|off;Price per tool. Needs l402 on; for the location, set there or inherited — nginx refuses to start otherwise.
l402_mcp_tool <name> <msat>;One tool’s price. Repeat per tool; the name is compared exactly with the decoded Mcp-Name.
l402_mcp_charge <method>...;Methods that cost money. Default tools/call. Also accepts resources/read (priced by URI) and prompts/get, the other methods that carry an Mcp-Name.
l402_mcp_upstream_validates on|off;Declares that the upstream rejects a request whose Mcp-Method / Mcp-Name disagree with its body. Required by l402_mcp on.

All four inherit into nested locations like the other l402_* directives. Everything else — Cashu, auto-detect, rate limits, dry run, tenants, realms, l402_indefinite_access — works on an MCP location as on any other.

Pricing and Redis

The price of a call is the first of:

  1. the tool’s Redis key, mcp-tool:<path>:<tool>
  2. the tool’s l402_mcp_tool line
  3. the location’s Redis key (<path>, as in Redis & Dynamic Config)
  4. l402_amount_msat_default

In the Redis key the tool name is percent-encoded except for letters, digits and -_.~/:

SET mcp-tool:/mcp:summarize 8000
SET "mcp-tool:/mcp:get%20weather" 2000     # tool "get weather"

The 402 response

An unpaid tool call gets 402 with the usual WWW-Authenticate: L402 … header (and X-Cashu when Cashu is on), so existing L402 clients work unchanged. The body is a JSON-RPC error an MCP client can read:

{
  "jsonrpc": "2.0",
  "error": {
    "code": 402,
    "message": "Payment required to call summarize",
    "data": {
      "tool": "summarize",
      "amount_msat": 5000,
      "www_authenticate": "L402 macaroon=\"…\", invoice=\"lnbc…\"",
      "macaroon": "…",
      "invoice": "lnbc…"
    }
  }
}

MCP defines no payment error, and the 2026-07-28 spec asks for new codes outside the JSON-RPC server range (-32768 to -32000), so the code is 402. -32002 would read as “resource not found” to MCP clients. l402_payment_html does not apply to MCP calls; they always get JSON.

Limitations

  • Older clients (protocol versions before 2026-07-28) don’t send the headers and are refused, discovery included. Keep a separate plain l402 on; location for them if needed. Reading the body to support them is planned.

  • Retries are new calls. A client that re-sends a tools/call — after an input-required result, or a dropped response stream — needs a new payment under the default replay check. MRTR retries carry a new JSON-RPC id, and the state tying them to the first call (requestState) is in the body, so the module can’t tell them from a fresh call. For tools that ask for input, let one payment cover a short window instead; the token still opens only its own tool and MCP method:

    location /mcp {
    # ...
    l402_indefinite_access on;   # a token works until it expires
    l402_macaroon_timeout  300;  # 5 minutes: room for the retries
}

  • stdio MCP servers have no HTTP to sit in front of.
